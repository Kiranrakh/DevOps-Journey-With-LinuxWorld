🤖 AUTOMATION - THE CORE IDEA
-----------------------------------------------------------------
Automation = "Let the system do repetitive tasks for you."

Ansible automates:
✔️ Configuration Management  
✔️ App Deployment  
✔️ Service Management  
✔️ File Operations  
✔️ Server Provisioning

💡 Goal: Define the "Desired State" and let Ansible enforce it.

-----------------------------------------------------------------
🛰️ AGENT PROGRAM - WHAT ANSIBLE DOESN’T NEED!
-----------------------------------------------------------------
Unlike other tools (like Puppet/Chef), Ansible is:
✅ Agentless  
✅ No daemon or background service required on target node  
✅ Connects via SSH (Linux) or WinRM (Windows)

Easy to manage — less maintenance.

-----------------------------------------------------------------
⚙️ ANSIBLE ENGINE
-----------------------------------------------------------------
Ansible Engine = The core that executes:
🔹 YAML Playbooks  
🔹 Ad-hoc Commands  
🔹 Ansible Modules

It interprets YAML files, communicates via SSH, and sends tasks
to target machines.

-----------------------------------------------------------------
📦 MODULES - TASK EXECUTORS
-----------------------------------------------------------------
Modules = Small programs used to perform tasks.

Examples:
- `yum`, `apt` → Package management  
- `file` → Manage files/directories  
- `copy` → Transfer files  
- `debug` → Print messages  
- `service` → Manage services

➡️ You can use modules in:
- Ad-Hoc Commands  
- Tasks inside Playbooks

-----------------------------------------------------------------
📈 CURRENT STATE vs DESIRED STATE
-----------------------------------------------------------------
Ansible works on **Idempotency**.

🟢 Desired State:
   The configuration you define in playbooks.

🔴 Current State:
   The actual state on the server.

➡️ Ansible checks if the Current ≠ Desired  
➡️ If yes, it takes action to fix it.

Repeat runs do NOT reapply changes if not needed.

📦 Configuration Management
------------------------------------------------------------
Configuration Management is the process of maintaining systems
in a desired, consistent state.

Ansible allows you to:
✅ Install & configure software
✅ Manage files, users, packages
✅ Ensure services are running
✅ Deploy applications

Everything is defined as code (Infrastructure as Code - IaC).

------------------------------------------------------------
🖥️ Controller Node & Target Node
------------------------------------------------------------
🔹 Controller Node:
   - Where Ansible is installed
   - Runs Ansible commands and playbooks

🔹 Target Node (Managed Node):
   - The systems/devices Ansible controls via SSH

➡️ Connection is SSH-based (agentless).

------------------------------------------------------------
🗂️ Creating Inventory
------------------------------------------------------------
The **inventory** file lists target machines (IP/hostname).

📁 Example: `hosts` file

```

\[web]
192.168.56.10
192.168.56.11

\[db]
192.168.56.12 ansible\_user=ec2-user ansible\_ssh\_private\_key\_file=\~/.ssh/id\_rsa

````

💡 Groups help manage multiple servers efficiently.

------------------------------------------------------------
🔐 Password Authentication & PermitRootLogin
------------------------------------------------------------
1. **Enable Password Login (Optional, not recommended):**
   - Edit `/etc/ssh/sshd_config` on target node:
     ```
     PasswordAuthentication yes
     PermitRootLogin yes
     ```
   - Restart SSH:
     ```
     sudo systemctl restart sshd
     ```

2. **Use password with Ansible:**
   - Add `--ask-pass` flag to prompt for password:
     ```
     ansible all -m ping --ask-pass
     ```

⚠️ For production, prefer **key-based authentication**.

------------------------------------------------------------
⚡ Adhoc Commands
------------------------------------------------------------
Used for one-time, simple automation tasks.

📁 Examples:
````

ansible all -m ping
ansible web -m shell -a "uptime"
ansible db -m yum -a "name=httpd state=present"
ansible web -m service -a "name=httpd state=started"

```

Useful for:
✅ Quick health checks  
✅ Remote package installs  
✅ Starting/stopping services

------------------------------------------------------------
🌐 Configure Apache HTTPD Web Server
------------------------------------------------------------

🔸 Using Ad-Hoc Commands:
```

ansible web -m yum -a "name=httpd state=present"
ansible web -m service -a "name=httpd state=started enabled=yes"
ansible web -m copy -a "content='Welcome to DevOps!' dest=/var/www/html/index.html"

````

🔸 Using Playbook:

📁 `apache_setup.yml`
```yaml
---
- name: Install and Configure Apache Web Server
  hosts: web
  become: yes

  tasks:
    - name: Install Apache
      yum:
        name: httpd
        state: present

    - name: Start and enable Apache
      service:
        name: httpd
        state: started
        enabled: yes

    - name: Deploy index.html
      copy:
        content: "<h1>Welcome to DevOps!</h1>"
        dest: /var/www/html/index.html
````

➡️ Run the playbook:

```
ansible-playbook apache_setup.yml
```

## 📘 Playbook - What Is It?

A Playbook is a YAML file where you write tasks to automate.

It contains:
✅ Hosts definition
✅ Tasks with modules
✅ Handlers, variables, roles

➡️ Reusable and scalable.

---

## 📑 YAML Language & Syntax (Yet Another Markup Language)

YAML is clean, readable, and structured by **indentation**.

🔹 Rules:

* Use spaces, not tabs
* Indentation is critical
* Start with `---` to denote a YAML file

📁 Example Task:

```yaml
- name: Install nginx
  yum:
    name: nginx
    state: present
```

💡 Every task has:
✔️ `name` (description)
✔️ Module name (e.g., `yum`)
✔️ Arguments (indented key-value pairs)
