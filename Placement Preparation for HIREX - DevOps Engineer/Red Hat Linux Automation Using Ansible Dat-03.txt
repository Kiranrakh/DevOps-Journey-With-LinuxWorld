=================================================================
                Ansible Automation - Full Concept Guide
=================================================================

🤖 AUTOMATION - THE CORE IDEA
-----------------------------------------------------------------
Automation = "Let the system do repetitive tasks for you."

Ansible automates:
✔️ Configuration Management  
✔️ App Deployment  
✔️ Service Management  
✔️ File Operations  
✔️ Server Provisioning

💡 Goal: Define the "Desired State" and let Ansible enforce it.

-----------------------------------------------------------------
🛰️ AGENT PROGRAM - WHAT ANSIBLE DOESN’T NEED!
-----------------------------------------------------------------
Unlike other tools (like Puppet/Chef), Ansible is:
✅ Agentless  
✅ No daemon or background service required on target node  
✅ Connects via SSH (Linux) or WinRM (Windows)

Easy to manage — less maintenance.

-----------------------------------------------------------------
⚙️ ANSIBLE ENGINE
-----------------------------------------------------------------
Ansible Engine = The core that executes:
🔹 YAML Playbooks  
🔹 Ad-hoc Commands  
🔹 Ansible Modules

It interprets YAML files, communicates via SSH, and sends tasks
to target machines.

-----------------------------------------------------------------
📦 MODULES - TASK EXECUTORS
-----------------------------------------------------------------
Modules = Small programs used to perform tasks.

Examples:
- `yum`, `apt` → Package management  
- `file` → Manage files/directories  
- `copy` → Transfer files  
- `debug` → Print messages  
- `service` → Manage services

➡️ You can use modules in:
- Ad-Hoc Commands  
- Tasks inside Playbooks

-----------------------------------------------------------------
📈 CURRENT STATE vs DESIRED STATE
-----------------------------------------------------------------
Ansible works on **Idempotency**.

🟢 Desired State:
   The configuration you define in playbooks.

🔴 Current State:
   The actual state on the server.

➡️ Ansible checks if the Current ≠ Desired  
➡️ If yes, it takes action to fix it.

Repeat runs do NOT reapply changes if not needed.
