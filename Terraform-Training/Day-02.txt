
===============================================================
               TERRAFORM: ADVANCED CONCEPTS
===============================================================

1. IMPERATIVE vs DECLARATIVE WAY OF CODE
----------------------------------------
Imperative:
- You write step-by-step instructions (HOW to do it).
- Example: Shell scripts or manual CLI commands.

Declarative:
- You define the desired end state (WHAT you want).
- Terraform is declarative.
- Example: “I want an EC2 instance with t2.micro size and X AMI.”

Terraform reads the configuration and figures out the steps automatically.

---------------------------------------------------------------

2. DESIRED STATE vs CURRENT STATE
----------------------------------
Terraform maintains two states:
- Desired State: Defined in your `.tf` files.
- Current State: What exists in the real world (cloud infra).

Terraform compares both and makes changes only where needed.

---------------------------------------------------------------

3. IDEMPOTENT CONCEPT
----------------------
- Idempotency means running the same configuration multiple times results in the same infrastructure.
- Example: If an EC2 instance already exists, Terraform won’t create another one unless you change something.
- Helps avoid duplicate resources and ensures consistency.

---------------------------------------------------------------

4. VARIABLES IN TERRAFORM
--------------------------
Variables help make your code reusable and cleaner.

Declare a variable in `variables.tf`:
variable "region" {
  type    = string
  default = "us-east-1"
}

Use it in `main.tf`:
provider "aws" {
  region = var.region
}

---------------------------------------------------------------

5. CREATING LIST IN TERRAFORM
------------------------------
List type variable:
variable "instance_types" {
  type    = list(string)
  default = ["t2.micro", "t2.small", "t2.medium"]
}

Accessing list elements:
var.instance_types[0]  # t2.micro

---------------------------------------------------------------

6. ASSIGNING MULTILINE VALUES TO A VARIABLE
--------------------------------------------
Use HEREDOC syntax (<<EOF ... EOF)

Example:
variable "my_script" {
  default = <<EOT
#!/bin/bash
sudo apt update
sudo apt install -y nginx
EOT
}

---------------------------------------------------------------

7. AUTO APPROVE IN TERRAFORM
-----------------------------
Use `-auto-approve` flag with apply/destroy command to skip interactive approval.

Example:
terraform apply -auto-approve
terraform destroy -auto-approve

---------------------------------------------------------------

8. STORING SENSITIVE DATA IN VARIABLE
--------------------------------------
Mark a variable as sensitive to hide it in output/logs:

Example:
variable "db_password" {
  type      = string
  sensitive = true
}

---------------------------------------------------------------

9. MAP TYPE VARIABLE
---------------------
Map helps define key-value pairs for complex configurations.

Example:
variable "instance_ami_map" {
  type = map(string)
  default = {
    us-east-1 = "ami-1234abcd"
    us-west-1 = "ami-abcd1234"
  }
}

Use:
ami = var.instance_ami_map["us-east-1"]

---------------------------------------------------------------

10. OUTPUT VARIABLES IN TERRAFORM
----------------------------------
Output variables are used to display values after Terraform creates or modifies infrastructure.

Example:
output "instance_public_ip" {
  value = aws_instance.web.public_ip
}

Command:
terraform output
terraform output instance_public_ip

Sensitive output:
output "db_password" {
  value     = var.db_password
  sensitive = true
}
